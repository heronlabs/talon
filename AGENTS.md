# talon

Go agent for Heron Labs Easypanel hosts: one static binary with four commands, `version`, `setup`, `doctor` and `report`. `README.md` describes what they do.

## Map

| Path | Holds |
|---|---|
| `src/main.go` | The entry point: picks the command from `os.Args[1]`. Its `version` variable is set at build time by `-X main.version`; without the flag it is `0.0.0-dev`. The configuration directory is `/etc/talon`, or `TALON_CONFIG_DIR`; the Docker socket is `/var/run/docker.sock`, or `DOCKER_SOCKET`. Both defaults are consts at the top, and `envOrDefault` takes the environment variable or, when it is empty, the default. It builds one instance of each service and command at the top: the logger is `slog.Default()`, the socket client times out after 5 seconds and the webhook client after 15, and `ReportService` receives `os.Hostname` and `time.Now`. Each case only runs `os.Exit(command.Run())`. |
| `src/application/` | One command per file, `command_<name>.go`: `VersionCommand`, `DoctorCommand`, `SetupCommand` and `ReportCommand`. Beside each command but `VersionCommand` is the interface of the service it runs: `Doctor`, `Setup` and `Report`. Each command receives that service, or `VersionCommand` the version, and a `*slog.Logger`, logs one line with the result and returns the exit code, `0` on success or `1` on failure. `Report` returns the `*entity.Report` it built, and `ReportCommand` logs it as JSON in `payload` on its `status=ok` line. |
| `src/core/` | `service_doctor.go`: `HealthCheck` interface and `DoctorService`, whose `Check` fails when `.env` does not exist or its mode is not `600` (`config:`) and when the Docker Engine does not answer the ping (`docker:`). `service_setup.go`: `ConfigReader` and `ConfigWriter` interfaces and `SetupService`, whose `Configure` reads the configuration and writes it to `.env` (`config:`). `service_report.go`: `ConfigGetter`, `ReportCollector` and `ReportSender` interfaces and `ReportService`, whose `Send` reads `WEBHOOK_URL` and, when that is read, `WEBHOOK_TOKEN` through `Get` (`config:`), takes the host from the injected hostname function, the hostname of the machine (`host:`), collects the `docker.Snapshot` (`docker:`), builds the report with `entity.NewReport` from the host, the injected clock, the version and the snapshot, and sends it to `WEBHOOK_URL` with the token (`webhook:`). Without `WEBHOOK_URL` it still collects and builds the report, and sends nothing. It returns the report, sent or not. |
| `src/core/entity/` | The report, one struct per file with its JSON tags, each filled from the `docker` types it reads. `entity_report.go`: `Report` and `NewReport(host, measuredAt, version, snapshot)`, which fills the host, `measuredAt` in RFC3339Nano UTC, `agent.version`, the system from `NewSystem` and the projects from `NewProjects`, `[]` without any. `entity_system.go`: `System` and `NewSystem`, from a `docker.DiskUsage`: the image and build cache sizes in GB. `entity_project.go`: `Project` and `NewProjects`, from a `docker.Snapshot`: each Swarm service named `<project>_<service>`, split on the first `_`, under its project, in the order the projects first appear; services without `_` are skipped. `entity_service.go`: `Service` and `NewService`, from a `docker.SwarmService` and the `docker.Snapshot`: its state (the most alive state of its containers, matched by `docker.ServiceNameLabel`; `removing` counts as `exited`, an unknown state as `dead`, and `missing` without any), replicas, failed or rejected tasks, limits and the size of its named volumes, then `addStats` with the `docker.ContainerStats` of each of its containers in the snapshot: memory without the inactive file, CPU where 100 is one core, network and block I/O. `entity_agent.go` (`Agent`), `entity_last_reconcile.go` (`LastReconcile`) and `entity_reconcile.go` (`Reconcile`) are data only. |
| `src/infrastructure/docker/` | `SocketClient` (`client_socket.go`): the `*http.Client` over the unix socket that every service of the package receives in its constructor. Its `Get(path, target)` requests `http://docker<path>`, wraps `ErrUnexpectedStatus` on an answer other than `200` and decodes the JSON into `target` unless it is nil. `HealthCheckService`, which pings the Engine API. `service_report_collector.go`: `ServiceNameLabel`, the label `com.docker.swarm.service.name` with the Swarm service of a container, and `ReportCollectorService`, whose `Collect` returns a `Snapshot` from `/system/df`, `/services?status=true`, `/tasks`, `/containers/json?all=true` filtered by `ServiceNameLabel`, and `/containers/{id}/stats?stream=false` of each running container, by its ID; it builds nothing else. The Engine API answers decode into exported structs that are data only, one per `response_<name>.go` (`DiskUsage`, `SwarmService`, `SwarmTask`, `Container`, `ContainerStats`, `CPUStats`), and `response_snapshot.go` holds `Snapshot`, the answers of one `Collect`. |
| `src/infrastructure/environment/` | `service_config_reader.go`: `Key` (name, default, whether it is a secret, whether it is optional and the key it depends on; required when it has no default and is not optional), `Keys()`, every variable of the `.env` in the order `setup` asks for them (`WEBHOOK_TOKEN` depends on `WEBHOOK_URL`), the `Prompt` interface and `ConfigReaderService`, whose `Read` takes each key from the environment variable or, when that is empty, from the prompt, with the value in `.env` or the default as fallback, leaves empty without asking a key whose dependency is empty, and fails listing the required keys left empty, and whose `Get` takes one key from the environment variable, then `.env`, then the default, without asking, and fails only when `.env` cannot be parsed. `service_config_writer.go`: `ConfigWriterService`, which receives the configuration directory, opens an `os.Root` on it inside `Write`, writes `.env.tmp` with mode `600` through it and renames it to `.env`. `.env.example` at the root repeats the list by hand. |
| `src/infrastructure/terminal/` | `PromptService`, which asks one question per line, shows the fallback in brackets (`****` for a secret) and returns it on an empty answer. |
| `src/infrastructure/webhook/` | `client_http.go`: `NewHTTPClient(timeout)`, the `*http.Client` with that timeout that the sender receives. `response_report.go`: `ReportResponse`, the reply of the webhook to a report (`data` with `host`, `measuredAt`, `outcome`, `matched` and `unmatched`). `service_report_sender.go`: `ReportSenderService`, which receives only the `*http.Client` and knows nothing about the configuration: its `Send(endpoint, token, report)` posts the `entity.Report` as JSON to `endpoint` as given, with `Authorization: Bearer <token>` only when `token` is not empty, and returns the reply decoded into a `ReportResponse`. An answer outside `2xx` wraps `ErrUnexpectedStatus`. |
| `tests/cli/` | Harness that runs the built binary (`TALON_BIN`) with a configuration directory (`TALON_CONFIG_DIR`), from an empty working directory, and returns output and exit code: `Run` with no input, `RunWithInput` with the given standard input. |
| `tests/commands/` | Integration tests (`//go:build integration`), one file per command, against the real binary, a temp directory and a fake Docker Engine on a unix socket. |
| `.docker/` | The fake VPS: Ubuntu 22.04 with systemd, Docker Engine and Easypanel. The image installs the `.deb` that `make package` builds in its build stage, which copies `Makefile`, `nfpm.yaml`, `version.txt`, `src` and `packaging`: the binary is at `/usr/bin/talon`. `.docker/config`, ignored by git, is mounted at `/etc/talon`. |
| `packaging/` | `talon-upgrade.service`, a oneshot that runs only when `/etc/apt/sources.list.d/talon.list` exists: `apt-get update` of that list alone, then `apt-get install --only-upgrade talon`. `talon-upgrade.timer` starts it every 15 minutes, with a random delay of up to 5 minutes. `postinstall`, `preremove` and `postremove`, the maintainer scripts of the `.deb`, follow what debhelper generates for a timer, with `deb-systemd-helper` and `deb-systemd-invoke`: install enables and starts the timer unless the admin disabled it; with `TALON_NO_UPDATES` set, it disables and stops it, and later upgrades keep it disabled. They never restart the service: the upgrade runs inside it. |
| `nfpm.yaml` | The `.deb`: the Linux binary at `/usr/bin/talon`, the directory `/etc/talon`, the two units of `packaging/` in `/usr/lib/systemd/system` and its three maintainer scripts. `make package` passes `ARCH` and `VERSION`. |
| `.github/workflows/` | `continuous-integration.yml` (pull requests) and `continuous-deployment.yml` (on `main`): the `release` job cuts the release and attaches `talon-linux-amd64` and `talon_<version>_amd64.deb`; the `publish` job runs `heronlabs/action-apt-repository@v1`, which builds and signs the apt repository from the `.deb` of the release and publishes it through `heronlabs/action-web-server`. `publish` runs in the `main` environment, assumes its AWS role through OIDC and reads the variables `APT_BUCKET_NAME`, `APT_AWS_REGION`, `APT_AWS_ROLE_TO_ASSUME` and `APT_DISTRIBUTION_ID` of the `main` environment. The signing key is the SSM parameter `/talon/APT_GPG_PRIVATE_KEY`, an armored private key with no passphrase. |
| `.githooks/pre-commit` | gofmt, build, vet and unit tests when staged changes touch Go files, `go.mod` or `go.sum`. |

Import rules, enforced by `depguard` in `.golangci.yml`: `core` imports nothing from `application`; `core/entity` imports only the standard library and `infrastructure/docker`, where its data comes from; `infrastructure` never imports `application`. `core` imports `infrastructure` only for the types of its interfaces: `docker.Snapshot` in `ReportCollector` and `webhook.ReportResponse` in `ReportSender`. Each interface is declared by the package that consumes it, in the file of its consumer, with the smallest method set that consumer needs; the implementing packages export only their implementations. `application` declares `Doctor` for `DoctorCommand`, `Setup` for `SetupCommand` and `Report` for `ReportCommand`. `core` declares `HealthCheck` for `DoctorService`, `ConfigReader` and `ConfigWriter` for `SetupService`, and `ConfigGetter`, `ReportCollector` and `ReportSender` for `ReportService`. `environment` declares `Prompt` for `ConfigReaderService`. So `application` imports only `core/entity`, for the report that `Report` returns, and `environment` imports nothing from talon.

## Commands

| Command | Does |
|---|---|
| `make build` | Static binary in `bin/talon` (`GOOS`, `GOARCH`, `VERSION`, `BIN` overridable) |
| `make package` | Linux binary and its `.deb` in `dist/`, through nfpm (`GOARCH` and `VERSION` overridable) |
| `make lint` | golangci-lint (with gofmt and goimports), actionlint, shellcheck (also on the maintainer scripts in `packaging/`), `go mod tidy -diff` |
| `make lint:fix` | golangci-lint with `--fix` |
| `make test` | Unit tests with the race detector; coverage in `.coverage/unit/` |
| `make test:integration` | Builds an instrumented binary with version `1.2.3` and runs `tests/`; coverage in `.coverage/integration/` |
| `make test:mutation` | gremlins over `src/`, `main.go` excluded, with a timeout coefficient of 20 so a warm test cache does not time mutants out; report in `.coverage/mutation/mutation.json` |
| `make audit` | govulncheck |
| `make up` / `make down` | Start and stop the fake VPS |
| `make watch` | Rebuild the Linux binary into `bin/linux` on every `.go` change; the fake VPS mounts it at `/usr/local/bin`, ahead of the packaged binary on its `PATH` |

`golangci-lint` and `shellcheck` come from brew locally. `actionlint`, `govulncheck`, `gremlins`, `air` and `nfpm` are `go tool`s pinned in `go.mod`. The target names use a colon (`test:integration`), not a dash.

## Conventions

- **Tests:** one `Test<Type>` per source file, in the same package (`command_version.go` and `TestVersionCommand` in `command_version_test.go`), and one `t.Run("Should ...")` per scenario. No table tests, no `for`/`range`. Arrange, act and assert are separated by blank lines, and the single assertion is the last statement: one `if` with one `t.Errorf`. Setup failures use `t.Fatal` inside helpers marked `t.Helper()`. The entities with logic have tests, built from `docker` values decoded from JSON; the data-only entities (`Agent`, `LastReconcile`, `Reconcile`), `response_*.go` and `client_*.go` have none: the entities and services that use them cover them.
- **Fakes** are written by hand in the test file that uses them (`fakeHealthCheck`), and implement the interfaces of the consumer, declared in the package under test. The filesystem enters as `fs.FS` for reads, and tests pass `fstest.MapFS`; writes go through an `*os.Root` the writer opens on its directory, and tests pass `t.TempDir()`.
- **Integration tests** assert the exit code and the output of the real binary in one condition.
- **Docs:** every declaration, exported or not, has a doc comment that starts with its name and says what it does or holds; a `const` block has one comment for the block. No comment goes inside a function body: a body that does more than one step calls documented, declarative functions, so it reads as a sequence of steps. Each package has its package comment in a `doc.go`. revive checks the exported identifiers and the package comments.
- **Mutants:** a surviving equivalent mutant is fixed by refactoring the code, not by excluding it.
- **Dependencies** enter through constructors (`New<Type>`). Only `main.go` wires.
- **The runtime uses only the standard library.** Every module in `go.mod` is there for a development tool.
- **Errors** wrap with `%w` and a short context prefix (`config:`, `docker:`). `ErrUnexpectedStatus` is a sentinel that tests match with `errors.Is`.
- **Logs** go through `log/slog`: commands log through the injected `*slog.Logger`, one line per result.
- **File names:** the kind comes first, so the explorer groups files by kind: `command_<name>.go` in `application`, `entity_<name>.go` in `core/entity`, `service_<name>.go` in `core` and `infrastructure`, and `response_<name>.go` (an answer of an external API) and `client_<name>.go` in `infrastructure`. A test keeps the name of its file plus `_test.go` (`command_setup_test.go`).
- **Responses and entities:** `response_<name>.go` holds only the struct of an API answer, with no method, function or const; the logic that reads it lives in the entity it fills. Each entity struct has its own `entity_<name>.go`, with the constructor and methods that fill it from the types it reads.
- **Never edit `version.txt` or `CHANGELOG.md`:** the release action owns them.
- **Every change goes through `/supera:ship`:** worktree, pull request, CI green. Nothing is committed to `main` directly and merging is a human action.
