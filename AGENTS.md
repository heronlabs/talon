# talon

Go agent for Heron Labs Easypanel hosts: one static binary with five commands, `version`, `setup`, `doctor`, `report` and `daemon`. `README.md` describes what they do.

## Map

| Path | Holds |
|---|---|
| `src/main.go` | The entry point: picks the command from `os.Args[1]`. Its `version` variable is set at build time by `-X main.version`; without the flag it is `0.0.0-dev`. The configuration directory is `/etc/talon`, or `TALON_CONFIG_DIR`; the Docker socket is `/var/run/docker.sock`, or `DOCKER_SOCKET`; the root of the host is `/`, or `TALON_HOST_ROOT`. The three defaults are consts at the top, and `envOrDefault` takes the environment variable or, when it is empty, the default. It builds one instance of each service and command at the top: the logger is `slog.Default()`, the prompt receives an `EchoClient` on the descriptor of `os.Stdin`, the socket client times out after 5 seconds and the HTTP client after 15, the one `webhook.NewHTTPClient` builds, shared by the webhook sender, the manifest reader and the `easypanel.APIClient`, which feeds `easypanel.ConfigCollectorService` and `easypanel.HealthCheckService`, one `os.DirFS` of the root of the host feeds `host.ReportCollectorService`, which also receives the path of that root, and `easypanel.ReportCollectorService`, `DoctorService` receives the docker health check, the configuration reader and the Easypanel health check, and `ReportService` receives the docker, host and easypanel collectors, the manifest reader, the Easypanel configuration collector, `os.Hostname` and `time.Now`; `ScheduleService` receives the same configuration reader, and `DaemonCommand` receives `ScheduleService`, the `ReportCommand` as its cycle and `time.Tick`. Each case only runs `os.Exit(command.Run())`; `doctor`, `report` and `daemon` pass it `signalContext()`, a context that is done on SIGTERM or SIGINT, so only those three catch the signals and Ctrl+C still ends `setup`: while a secret is typed, `EchoClient` catches them only to turn the echo back on and raise them again. `signalContext` drops the stop function of `signal.NotifyContext`, since the process exits after the command. |
| `src/application/cli/` | One command per file, `command_<name>.go`: `VersionCommand`, `DoctorCommand`, `SetupCommand`, `ReportCommand` and `DaemonCommand`. Beside each command but `VersionCommand` is the interface of the service it runs: `Doctor`, `Setup`, `Report`, and `Schedule` and `Cycle` for `DaemonCommand`. Each command receives that service, or `VersionCommand` the version, and a `*slog.Logger`, logs one line with the result and returns the exit code, `0` on success or `1` on failure; `DoctorCommand`, `ReportCommand` and `DaemonCommand` take a `context.Context` in `Run(ctx)` and pass it on. `Report` returns the `*domain.Report` it built, and `ReportCommand` logs it as JSON in `payload` on its `status=ok` line. `DaemonCommand` also receives its cycle through `Cycle` (`Run(ctx) int`, the `ReportCommand`) and the function that gives the ticks of an interval: its `Run(ctx)` reads the interval and the timeout through `Schedule` (`1` on failure), runs a cycle at once and one on every tick, one at a time, each under `context.WithTimeout(context.WithoutCancel(ctx), timeout)`, so ctx being done never cancels the cycle in flight, and goes on whatever the cycle returns, since the cycle logs its own line. When ctx is done it starts no other cycle, even with a tick pending, logs `status=stopped` and returns `0`. |
| `src/core/` | `service_doctor.go`: `HealthCheck` and `EasypanelHealthCheck` interfaces and `DoctorService`, whose `Check(ctx)` fails when `.env` does not exist or its mode is not `600` (`config:`), when the Docker Engine does not answer the ping before ctx is done (`docker:`), when `EASYPANEL_URL` and `EASYPANEL_TOKEN`, read in one `Get`, cannot be read (`config:`), and, only with `EASYPANEL_TOKEN` set, when the Easypanel API at `EASYPANEL_URL` refuses it (`easypanel:`). `service_setup.go`: `ConfigReader` and `ConfigWriter` interfaces and `SetupService`, whose `Configure` reads the configuration and writes it to `.env` (`config:`). `service_report.go`: `ConfigGetter`, `DockerCollector`, `HostCollector`, `EasypanelCollector`, `ManifestReader`, `EasypanelConfigCollector` and `ReportSender` interfaces and `ReportService`, whose `Send(ctx)` reads `WEBHOOK_URL`, `WEBHOOK_TOKEN`, `MANIFEST_URL`, `MANIFEST_TOKEN`, `EASYPANEL_URL` and `EASYPANEL_TOKEN` in one `Get`, so `.env` is parsed once per cycle (`config:`), takes the host from the injected hostname function, the hostname of the machine (`host:`), collects, in this order, the `docker.Snapshot`, requested with ctx (`docker:`), the `host.Snapshot` (`system:`) and the `easypanel.Snapshot` (`easypanel:`), then observes in `observe`: without `MANIFEST_URL` it reads nothing; otherwise it reads the `manifest.Manifest` at `MANIFEST_URL` with `MANIFEST_TOKEN` and ctx (`manifest:`) and only then the `easypanel.ConfigSnapshot` at `EASYPANEL_URL` with `EASYPANEL_TOKEN` and ctx (`easypanel:`), so a manifest failure makes no Easypanel call. An observation failure never fails the cycle: it returns the error, with the manifest when only Easypanel failed. It builds the report with `domain.NewReport` from the host, the injected clock, the version, the three snapshots, the manifest, the configuration of Easypanel and the error of the observation, and sends it to `WEBHOOK_URL` with the token and ctx (`webhook:`). Without `WEBHOOK_URL` it still collects and builds the report, and sends nothing. It returns the report, sent or not. `service_schedule.go`: `ScheduleService`, whose `Read` takes `INTERVAL_REPORT` through the same `ConfigGetter` and returns it as the interval and the shorter of it and `maxCycleTimeout`, one minute, as the timeout of a cycle; it fails when `INTERVAL_REPORT` cannot be read, is not a duration or is not positive (`config:`). |
| `src/core/domain/` | The report, one struct per file with its JSON tags, each filled from the `docker`, `host`, `easypanel` and `manifest` types it reads. `entity_report.go`: `Report` and `NewReport(hostname, measuredAt, version, snapshot, hostSnapshot, easypanelSnapshot, declared, configured, observeErr)`, which fills the host, `measuredAt` in RFC3339Nano UTC, the agent from `NewAgent` with the last reconcile from `NewLastReconcile` at `measuredAt`, the system from `NewSystem` and the projects from `NewProjects`, `[]` without any; `declared`, the `manifest.Manifest`, and `configured`, the `easypanel.ConfigSnapshot`, are nil when they were not read. `entity_agent.go`: `Agent` and `NewAgent`, from the version, the `docker.EasypanelPackage` of the snapshot and the last reconcile: `agent.version`, `lastReconcile` and, with a package, `easypanelVersion` and `easypanelSupported`, whether that version is in `supportedEasypanelVersions` (`2.36.0` and `2.37.0`); without a package both are null. `entity_system.go`: `System` and `NewSystem`, from a `docker.DiskUsage` and the `host.Snapshot`: the RAM and swap totals in GiB and their used, `MemTotal` less `MemAvailable` and `SwapTotal` less `SwapFree`, the disk total in GB and its used, the total less the free blocks, the load over 1, 5 and 15 minutes, the uptime in whole seconds, and the image and build cache sizes in GB. `entity_project.go`: `Project` and `NewProjects`, from a `docker.Snapshot`, the `easypanel.Snapshot`, the manifest and the configuration of Easypanel: each Swarm service named `<project>_<service>`, split on the first `_`, under its project, in the order the projects first appear, with the bytes of the directory `<project>/<service>` of the easypanel snapshot, then each client of the manifest without a Swarm service, by its slug, in the order of the manifest, with services `[]`; services without `_` are skipped. Then `reconcile` appends to each project the services its client declares without a Swarm service, in the order of its schema, from `NewMissingService`, and sets its reconcile from `NewReconcile`. Without the manifest there are no such projects or services. `entity_service.go`: `Service`, `NewMissingService`, a declared service without a Swarm service, `managed`, `missing` and with every number `0`, and `NewService`, from a `docker.SwarmService`, the `docker.Snapshot`, the bytes of its directory and the `manifest.Client` of its project, nil without one: `managed` when the client declares its name as the `serviceName` of the data of a service of its schema, its state (the most alive state of its containers, matched by `docker.ServiceNameLabel`; `removing` counts as `exited`, an unknown state as `dead`, and `missing` without any), replicas, failed or rejected tasks, limits and its disk, the size of its named volumes plus the bytes of its directory, then `addStats` with the `docker.ContainerStats` of each of its containers in the snapshot: memory without the inactive file, CPU where 100 is one core, network and block I/O. `entity_reconcile.go`: `Reconcile` and `NewReconcile`, from the name of the project, its `manifest.Client`, nil when the manifest does not list it, and the `easypanel.ConfigSnapshot`: nil without the snapshot, as without `MANIFEST_URL` or when the observation failed; `unmanaged` without the client; `converged` when the client declares at least one service and every one exists in the snapshot under the project and its name, with the same type and data that matches the declared one, and `pending` otherwise, so a client that declares no service is `pending`; `missingSecrets` `[]` and `error` null. `matches` is the generic comparison: an object on its declared keys only, recursively, but `ignoredKeys` (`projectName`, `serviceName`, `env` and `password`), an absent key reading as null; an array of the same length whose declared items each match a distinct configured item, in any order, `assign` trying every pairing; any other value, numbers included, as equal JSON values. `entity_last_reconcile.go`: `LastReconcile` and `NewLastReconcile`, from `measuredAt`, the manifest and the error of the observation: `failed` with the error, cut by `truncate` to `maxErrorLength` (500) characters, the limit of the CMS; nil without the manifest; `ok` with `error` null otherwise. |
| `src/infrastructure/docker/` | `SocketClient` (`client_socket.go`): the `*http.Client` over the unix socket that every service of the package receives in its constructor. Its `Open(ctx, path)` requests `http://docker<path>` with ctx, returns `ErrNotFound` on an answer `404`, wraps `ErrUnexpectedStatus` on any other answer than `200` and returns the body, which the caller closes; its `Get(ctx, path, target)` decodes the JSON of that body into `target` unless it is nil. `HealthCheckService`, whose `Ping(ctx)` pings the Engine API. `service_report_collector.go`: `ServiceNameLabel`, the label `com.docker.swarm.service.name` with the Swarm service of a container, and `ReportCollectorService`, whose `Collect(ctx)` returns a `Snapshot` from `/system/df`, `/services?status=true`, `/tasks`, `/containers/json?all=true` filtered by `ServiceNameLabel`, `/containers/{id}/stats?stream=false` of each running container, by its ID, at most `maxParallelStats` (8) at once, each request writing its own slot, and `/containers/{id}/archive?path=/app/package.json` of the first running container of the Swarm service `easypanel`, a tar whose first entry decodes into `EasypanelPackage`, nil without such a container. A container gone between the list and those two requests, as in a deploy, answers `404`: its stats are left out and the package is nil. Any other error of the stats, the first by the order of the containers, and any `404` elsewhere fail. It builds nothing else. The Engine API answers decode into exported structs that are data only, one per `response_<name>.go` (`DiskUsage`, `SwarmService`, `SwarmTask`, `Container`, `ContainerStats`, `CPUStats`, `EasypanelPackage`), and `response_snapshot.go` holds `Snapshot`, the answers of one `Collect`. |
| `src/infrastructure/host/` | `ReportCollectorService` (`service_report_collector.go`), which receives the `fs.FS` of the root of the host and the path of that root. Its `Collect` runs `syscall.Statfs` on the root first, so a root that does not exist fails there, then reads `proc/meminfo` (`MemTotal`, `MemAvailable`, `SwapTotal` and `SwapFree`, in kB), the first three numbers of `proc/loadavg` and the first number of `proc/uptime`, and returns a `Snapshot`; a missing file, or a value missing or not a number, fails. The parsing of `proc` lives in the collector. `response_disk.go` (`Disk`: the total and free bytes, the free being the free blocks, `Bfree`, so the total less the free is the Used of `df`), `response_memory.go` (`Memory`), `response_load.go` (`Load`), `response_uptime.go` (`Uptime`) and `response_snapshot.go` (`Snapshot`) are data only. |
| `src/infrastructure/easypanel/` | `ReportCollectorService` (`service_report_collector.go`), which receives the `fs.FS` of the root of the host. Its `Collect` sums the sizes of the regular files under each `etc/easypanel/projects/<project>/<service>/`, skipping the entries of `projects` and of a project that are not directories, and returns a `Snapshot` (`response_snapshot.go`, data only) with the bytes by project and then by service. Without `etc/easypanel/projects` it returns an empty snapshot; any other error reading or walking the directories fails. `APIClient` (`client_api.go`): the `*http.Client` the API services receive in their constructor; its `Get(ctx, endpoint, token, operation, query, target)` requests `GET <endpoint>/api/<operation>` with the query, ctx and `Authorization: Bearer <token>`, decodes the JSON answer into `target` and prefixes its error with the operation; an answer outside `2xx` wraps `ErrUnexpectedStatus`. `ConfigCollectorService` (`service_config_collector.go`), whose `Collect(ctx, endpoint, token)` lists the services with `listProjectsAndServices`, reads each `app`, `postgres` or `mysql` service with the operation of `inspectOperations` for its type, leaving out the other types, and the domains of each app with `listDomains`, and returns a `ConfigSnapshot` with a `ServiceConfig` (`type` and `data`) by project and then by service; the first request that fails fails it, and a listed service that is not found is a failure too. The normalization to the shape of the schema lives only here: `data` is the inspect answer, decoded as JSON values, without `droppedKeys` (`env`, `password`, the deploy `token` and `deploymentUrl`), and, for an app, with `domains`, each `listDomains` item in the shape of a domain of the schema from `schemaDomain`, its `port` and `internalProtocol` taken from its `serviceDestination`, as Easypanel's own `inspectProject` does. `HealthCheckService` (`service_health_check.go`), whose `Check(ctx, endpoint, token)` requests `getUser` and fails with `ErrTokenRefused` when it answers null, as Easypanel 2.36.0 does, with `200`, for a token it refuses. The answers decode into data-only structs: `ProjectsAndServices` (`response_projects_and_services.go`) with `ListedService` items (`response_listed_service.go`), `Domain` (`response_domain.go`) and `User` (`response_user.go`); `ConfigSnapshot` (`response_config_snapshot.go`) and `ServiceConfig` (`response_service_config.go`) hold the answers of one `Collect`. The package knows nothing about the Swarm `<project>_<service>` names. |
| `src/infrastructure/manifest/` | `ReaderService` (`service_reader.go`), which receives only the `*http.Client`: its `Read(ctx, endpoint, token)` requests `GET` of `endpoint` as given, with ctx and `Authorization: Bearer <token>` only when `token` is not empty, and returns the answer decoded into a `Manifest`; an answer outside `2xx` wraps `ErrUnexpectedStatus`. `response_manifest.go` (`Manifest`: `data` with `host` and `clients`), `response_client.go` (`Client`: `slug`, `lifecycle`, `secretsRoleArn`, null when empty, and `schema` with its `services`) and `response_service.go` (`Service`: `type` and `data`, decoded as `map[string]any`, since the comparison is generic) are data only. |
| `src/infrastructure/environment/` | `service_config_reader.go`: `Key` (name, default, whether it is a secret, whether it is optional and the key it depends on) and its `Required(values)`, whether it needs a value: it has no default, is not optional and its dependency, if any, is not empty in `values`; `Keys()`, every variable of the `.env` in the order `setup` asks for them (`WEBHOOK_TOKEN` depends on `WEBHOOK_URL`, and `MANIFEST_TOKEN`, `EASYPANEL_URL`, whose default is `http://localhost:3000`, and `EASYPANEL_TOKEN` on `MANIFEST_URL`), the `Prompt` interface and `ConfigReaderService`, whose `Read` takes each key from the environment variable or, when that is empty, from the prompt, with the value in `.env` or the default as fallback, leaves empty without asking a key whose dependency is empty, and fails listing the keys required among the values that are left empty, and whose `Get(names...)` returns the value of each name, by name, from the environment variable, then `.env`, then the default, with one parse of `.env` and without asking, and fails only when `.env` cannot be parsed. `service_config_writer.go`: `ConfigWriterService`, which receives the configuration directory, opens an `os.Root` on it inside `Write`, writes `.env.tmp` with mode `600` through it and renames it to `.env`. `.env.example` at the root repeats the list by hand. |

It reads the answer of a secret through `Echo`, declared beside it: `Off` turns the echo off and returns the function that turns it back on, which `PromptService` always runs, even when the read fails, and whether it turned it off; only when it did does `PromptService` write a newline after the answer, which the terminal did not echo. `EchoClient` (`client_echo.go`) implements it on a file descriptor with the termios ioctls of `syscall`, whose requests are the only consts of `client_echo_linux.go` and `client_echo_darwin.go`: when the termios cannot be read, as when the descriptor is not a terminal, `Off` changes nothing; otherwise it clears `ECHO` alone, so line editing and Ctrl+C still work, and until the echo is back on a SIGINT or SIGTERM sets the termios back and is raised again, so it still ends the process. |

Import rules, enforced by `depguard` in `.golangci.yml`: `core` imports nothing from `application`; `core/domain` imports only the standard library, `infrastructure/docker`, `infrastructure/host`, `infrastructure/easypanel` and `infrastructure/manifest`, where its data comes from; `infrastructure` never imports `application`. `core` imports `infrastructure` only for the types of its interfaces: `docker.Snapshot` in `DockerCollector`, `host.Snapshot` in `HostCollector`, `easypanel.Snapshot` in `EasypanelCollector`, `manifest.Manifest` in `ManifestReader`, `easypanel.ConfigSnapshot` in `EasypanelConfigCollector` and `webhook.ReportResponse` in `ReportSender`. Each interface is declared by the package that consumes it, in the file of its consumer, with the smallest method set that consumer needs; the implementing packages export only their implementations. `application/cli` declares `Doctor` for `DoctorCommand`, `Setup` for `SetupCommand`, `Report` for `ReportCommand`, and `Schedule` and `Cycle` for `DaemonCommand`. `core` declares `HealthCheck` and `EasypanelHealthCheck` for `DoctorService`, `ConfigReader` and `ConfigWriter` for `SetupService`, and `ConfigGetter`, `DockerCollector`, `HostCollector`, `EasypanelCollector`, `ManifestReader`, `EasypanelConfigCollector` and `ReportSender` for `ReportService`; `ScheduleService` and `DoctorService` consume the same `ConfigGetter`. `environment` declares `Prompt` for `ConfigReaderService`, and `terminal` declares `Echo` for `PromptService`. So `application/cli` imports only `core/domain`, for the report that `Report` returns, and `environment`, `host`, `easypanel` and `manifest` import nothing from talon.

## Conventions

- **Tests:** one `Test<Type>` per source file, in the same package (`command_version.go` and `TestVersionCommand` in `command_version_test.go`), and one `t.Run("Should ...")` per scenario. No table tests, no `for`/`range`. Arrange, act and assert are separated by blank lines, and the single assertion is the last statement: one `if` with one `t.Errorf`. Setup failures use `t.Fatal` inside helpers marked `t.Helper()`. The entities have tests, built from `docker` and `manifest` values decoded from JSON and `host` and `easypanel` values written as literals, the `data` of an `easypanel.ServiceConfig` decoded from JSON; `response_*.go` and `client_*.go` have none: the entities and services that use them cover them.
- **Fakes** are written by hand in the test file that uses them (`fakeHealthCheck`), and implement the interfaces of the consumer, declared in the package under test. The filesystem enters as `fs.FS` for reads, and tests pass `fstest.MapFS`, or `os.DirFS` of a `t.TempDir()` whose permissions they change when they need a read to fail; writes go through an `*os.Root` the writer opens on its directory, and tests pass `t.TempDir()`.
- **Integration tests** assert the exit code and the output of the real binary in one condition.
- **Docs:** every declaration, exported or not, has a doc comment that starts with its name and says what it does or holds; a `const` block has one comment for the block. No comment goes inside a function body: a body that does more than one step calls documented, declarative functions, so it reads as a sequence of steps. Each package has its package comment in a `doc.go`. revive checks the exported identifiers and the package comments.
- **Mutants:** a surviving equivalent mutant is fixed by refactoring the code, not by excluding it.
- **Dependencies** enter through constructors (`New<Type>`). Only `main.go` wires.
- **The runtime uses only the standard library.** Every module in `go.mod` is there for a development tool.
- **Errors** wrap with `%w` and a short context prefix (`config:`, `docker:`, `manifest:`, `easypanel:`). `ErrUnexpectedStatus`, `ErrNotFound` and `ErrTokenRefused` are sentinels that tests match with `errors.Is`.
- **Logs** go through `log/slog`: commands log through the injected `*slog.Logger`, one line per result.
- **File names:** the kind comes first, so the explorer groups files by kind: `command_<name>.go` in `application/cli`, `entity_<name>.go` in `core/domain`, `service_<name>.go` in `core` and `infrastructure`, and `response_<name>.go` (an answer of an external API) and `client_<name>.go` in `infrastructure`. A test keeps the name of its file plus `_test.go` (`command_setup_test.go`).
- **Responses and entities:** `response_<name>.go` holds only the struct of an API answer, with no method, function or const; the logic that reads it lives in the entity it fills. Each entity struct has its own `entity_<name>.go`, with the constructor and methods that fill it from the types it reads.
- **Never edit `version.txt` or `CHANGELOG.md`:** the release action owns them.
- **Every change goes through `/supera:ship`:** worktree, pull request, CI green. Nothing is committed to `main` directly and merging is a human action.
