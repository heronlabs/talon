# talon

Go agent for Heron Labs Easypanel hosts: one static binary with five commands, `version`, `setup`, `doctor`, `report` and `daemon`. `README.md` describes what they do.

## Map

| Path | Holds |
|---|---|
| `src/main.go` | The entry point: picks the command from `os.Args[1]`. Its `version` variable is set at build time by `-X main.version`; without the flag it is `0.0.0-dev`. The configuration directory is `/etc/talon`, or `TALON_CONFIG_DIR`; the Docker socket is `/var/run/docker.sock`, or `DOCKER_SOCKET`; the root of the host is `/`, or `TALON_HOST_ROOT`. The three defaults are consts at the top, and `envOrDefault` takes the environment variable or, when it is empty, the default. It builds one instance of each service and command at the top: the logger is `slog.Default()`, the prompt receives an `EchoClient` on the descriptor of `os.Stdin`, the socket client times out after 5 seconds and the webhook client after 15, one `os.DirFS` of the root of the host feeds `host.ReportCollectorService`, which also receives the path of that root, and `easypanel.ReportCollectorService`, and `ReportService` receives the docker, host and easypanel collectors, `os.Hostname` and `time.Now`; `ScheduleService` receives the same configuration reader, and `DaemonCommand` receives `ScheduleService`, the `ReportCommand` as its cycle and `time.Tick`. Each case only runs `os.Exit(command.Run())`; `doctor`, `report` and `daemon` pass it `signalContext()`, a context that is done on SIGTERM or SIGINT, so only those three catch the signals and Ctrl+C still ends `setup`: while a secret is typed, `EchoClient` catches them only to turn the echo back on and raise them again. `signalContext` drops the stop function of `signal.NotifyContext`, since the process exits after the command. |
| `src/application/` | One command per file, `command_<name>.go`: `VersionCommand`, `DoctorCommand`, `SetupCommand`, `ReportCommand` and `DaemonCommand`. Beside each command but `VersionCommand` is the interface of the service it runs: `Doctor`, `Setup`, `Report`, and `Schedule` and `Cycle` for `DaemonCommand`. Each command receives that service, or `VersionCommand` the version, and a `*slog.Logger`, logs one line with the result and returns the exit code, `0` on success or `1` on failure; `DoctorCommand`, `ReportCommand` and `DaemonCommand` take a `context.Context` in `Run(ctx)` and pass it on. `Report` returns the `*entity.Report` it built, and `ReportCommand` logs it as JSON in `payload` on its `status=ok` line. `DaemonCommand` also receives its cycle through `Cycle` (`Run(ctx) int`, the `ReportCommand`) and the function that gives the ticks of an interval: its `Run(ctx)` reads the interval and the timeout through `Schedule` (`1` on failure), runs a cycle at once and one on every tick, one at a time, each under `context.WithTimeout(context.WithoutCancel(ctx), timeout)`, so ctx being done never cancels the cycle in flight, and goes on whatever the cycle returns, since the cycle logs its own line. When ctx is done it starts no other cycle, even with a tick pending, logs `status=stopped` and returns `0`. |
| `src/core/` | `service_doctor.go`: `HealthCheck` interface and `DoctorService`, whose `Check(ctx)` fails when `.env` does not exist or its mode is not `600` (`config:`) and when the Docker Engine does not answer the ping before ctx is done (`docker:`). `service_setup.go`: `ConfigReader` and `ConfigWriter` interfaces and `SetupService`, whose `Configure` reads the configuration and writes it to `.env` (`config:`). `service_report.go`: `ConfigGetter`, `DockerCollector`, `HostCollector`, `EasypanelCollector` and `ReportSender` interfaces and `ReportService`, whose `Send(ctx)` reads `WEBHOOK_URL` and `WEBHOOK_TOKEN` in one `Get`, so `.env` is parsed once per cycle (`config:`), takes the host from the injected hostname function, the hostname of the machine (`host:`), collects, in this order, the `docker.Snapshot`, requested with ctx (`docker:`), the `host.Snapshot` (`system:`) and the `easypanel.Snapshot` (`easypanel:`), builds the report with `entity.NewReport` from the host, the injected clock, the version and the three snapshots, and sends it to `WEBHOOK_URL` with the token and ctx (`webhook:`). Without `WEBHOOK_URL` it still collects and builds the report, and sends nothing. It returns the report, sent or not. `service_schedule.go`: `ScheduleService`, whose `Read` takes `INTERVAL_REPORT` through the same `ConfigGetter` and returns it as the interval and the shorter of it and `maxCycleTimeout`, one minute, as the timeout of a cycle; it fails when `INTERVAL_REPORT` cannot be read, is not a duration or is not positive (`config:`). |
| `src/core/entity/` | The report, one struct per file with its JSON tags, each filled from the `docker`, `host` and `easypanel` types it reads. `entity_report.go`: `Report` and `NewReport(hostname, measuredAt, version, snapshot, hostSnapshot, easypanelSnapshot)`, which fills the host, `measuredAt` in RFC3339Nano UTC, the agent from `NewAgent`, the system from `NewSystem` and the projects from `NewProjects`, `[]` without any. `entity_agent.go`: `Agent` and `NewAgent`, from the version and the `docker.EasypanelPackage` of the snapshot: `agent.version` and, with a package, `easypanelVersion` and `easypanelSupported`, whether that version is in `supportedEasypanelVersions` (`2.36.0`); without a package both are null. `entity_system.go`: `System` and `NewSystem`, from a `docker.DiskUsage` and the `host.Snapshot`: the RAM and swap totals in GiB and their used, `MemTotal` less `MemAvailable` and `SwapTotal` less `SwapFree`, the disk total in GB and its used, the total less the free blocks, the load over 1, 5 and 15 minutes, the uptime in whole seconds, and the image and build cache sizes in GB. `entity_project.go`: `Project` and `NewProjects`, from a `docker.Snapshot` and the `easypanel.Snapshot`: each Swarm service named `<project>_<service>`, split on the first `_`, under its project, in the order the projects first appear, with the bytes of the directory `<project>/<service>` of the easypanel snapshot; services without `_` are skipped. `entity_service.go`: `Service` and `NewService`, from a `docker.SwarmService`, the `docker.Snapshot` and the bytes of its directory: its state (the most alive state of its containers, matched by `docker.ServiceNameLabel`; `removing` counts as `exited`, an unknown state as `dead`, and `missing` without any), replicas, failed or rejected tasks, limits and its disk, the size of its named volumes plus the bytes of its directory, then `addStats` with the `docker.ContainerStats` of each of its containers in the snapshot: memory without the inactive file, CPU where 100 is one core, network and block I/O. `entity_last_reconcile.go` (`LastReconcile`) and `entity_reconcile.go` (`Reconcile`) are data only. |
| `src/infrastructure/docker/` | `SocketClient` (`client_socket.go`): the `*http.Client` over the unix socket that every service of the package receives in its constructor. Its `Open(ctx, path)` requests `http://docker<path>` with ctx, returns `ErrNotFound` on an answer `404`, wraps `ErrUnexpectedStatus` on any other answer than `200` and returns the body, which the caller closes; its `Get(ctx, path, target)` decodes the JSON of that body into `target` unless it is nil. `HealthCheckService`, whose `Ping(ctx)` pings the Engine API. `service_report_collector.go`: `ServiceNameLabel`, the label `com.docker.swarm.service.name` with the Swarm service of a container, and `ReportCollectorService`, whose `Collect(ctx)` returns a `Snapshot` from `/system/df`, `/services?status=true`, `/tasks`, `/containers/json?all=true` filtered by `ServiceNameLabel`, `/containers/{id}/stats?stream=false` of each running container, by its ID, at most `maxParallelStats` (8) at once, each request writing its own slot, and `/containers/{id}/archive?path=/app/package.json` of the first running container of the Swarm service `easypanel`, a tar whose first entry decodes into `EasypanelPackage`, nil without such a container. A container gone between the list and those two requests, as in a deploy, answers `404`: its stats are left out and the package is nil. Any other error of the stats, the first by the order of the containers, and any `404` elsewhere fail. It builds nothing else. The Engine API answers decode into exported structs that are data only, one per `response_<name>.go` (`DiskUsage`, `SwarmService`, `SwarmTask`, `Container`, `ContainerStats`, `CPUStats`, `EasypanelPackage`), and `response_snapshot.go` holds `Snapshot`, the answers of one `Collect`. |
| `src/infrastructure/host/` | `ReportCollectorService` (`service_report_collector.go`), which receives the `fs.FS` of the root of the host and the path of that root. Its `Collect` runs `syscall.Statfs` on the root first, so a root that does not exist fails there, then reads `proc/meminfo` (`MemTotal`, `MemAvailable`, `SwapTotal` and `SwapFree`, in kB), the first three numbers of `proc/loadavg` and the first number of `proc/uptime`, and returns a `Snapshot`; a missing file, or a value missing or not a number, fails. The parsing of `proc` lives in the collector. `response_disk.go` (`Disk`: the total and free bytes, the free being the free blocks, `Bfree`, so the total less the free is the Used of `df`), `response_memory.go` (`Memory`), `response_load.go` (`Load`), `response_uptime.go` (`Uptime`) and `response_snapshot.go` (`Snapshot`) are data only. |
| `src/infrastructure/easypanel/` | `ReportCollectorService` (`service_report_collector.go`), which receives the `fs.FS` of the root of the host. Its `Collect` sums the sizes of the regular files under each `etc/easypanel/projects/<project>/<service>/`, skipping the entries of `projects` and of a project that are not directories, and returns a `Snapshot` (`response_snapshot.go`, data only) with the bytes by project and then by service. Without `etc/easypanel/projects` it returns an empty snapshot; any other error reading or walking the directories fails. It knows nothing about the Swarm `<project>_<service>` names. |
| `src/infrastructure/environment/` | `service_config_reader.go`: `Key` (name, default, whether it is a secret, whether it is optional and the key it depends on; required when it has no default and is not optional), `Keys()`, every variable of the `.env` in the order `setup` asks for them (`WEBHOOK_TOKEN` depends on `WEBHOOK_URL`), the `Prompt` interface and `ConfigReaderService`, whose `Read` takes each key from the environment variable or, when that is empty, from the prompt, with the value in `.env` or the default as fallback, leaves empty without asking a key whose dependency is empty, and fails listing the required keys left empty, and whose `Get(names...)` returns the value of each name, by name, from the environment variable, then `.env`, then the default, with one parse of `.env` and without asking, and fails only when `.env` cannot be parsed. `service_config_writer.go`: `ConfigWriterService`, which receives the configuration directory, opens an `os.Root` on it inside `Write`, writes `.env.tmp` with mode `600` through it and renames it to `.env`. `.env.example` at the root repeats the list by hand. |
| `src/infrastructure/terminal/` | `PromptService` (`service_prompt.go`), which asks one question per line, shows the fallback in brackets (`****` for a secret) and returns it on an empty answer. It reads the answer of a secret through `Echo`, declared beside it: `Off` turns the echo off and returns the function that turns it back on, which `PromptService` always runs, even when the read fails, and whether it turned it off; only when it did does `PromptService` write a newline after the answer, which the terminal did not echo. `EchoClient` (`client_echo.go`) implements it on a file descriptor with the termios ioctls of `syscall`, whose requests are the only consts of `client_echo_linux.go` and `client_echo_darwin.go`: when the termios cannot be read, as when the descriptor is not a terminal, `Off` changes nothing; otherwise it clears `ECHO` alone, so line editing and Ctrl+C still work, and until the echo is back on a SIGINT or SIGTERM sets the termios back and is raised again, so it still ends the process. |
| `src/infrastructure/webhook/` | `client_http.go`: `NewHTTPClient(timeout)`, the `*http.Client` with that timeout that the sender receives. `response_report.go`: `ReportResponse`, the reply of the webhook to a report (`data` with `host`, `measuredAt`, `outcome`, `matched` and `unmatched`). `service_report_sender.go`: `ReportSenderService`, which receives only the `*http.Client` and knows nothing about the configuration: its `Send(ctx, endpoint, token, report)` posts the `entity.Report` as JSON to `endpoint` as given, with ctx, with `Authorization: Bearer <token>` only when `token` is not empty, and returns the reply decoded into a `ReportResponse`. An answer outside `2xx` wraps `ErrUnexpectedStatus`. |
| `tests/cli/` | Harness that runs the built binary (`TALON_BIN`) with a configuration directory (`TALON_CONFIG_DIR`), from an empty working directory, and returns output and exit code: `Run` with no input, `RunWithInput` with the given standard input. `Start` starts it the same way without waiting and returns the running `Process`: `Signal` sends it a signal and `Wait` waits for it to exit, at most 30 seconds, and returns output and exit code; a process still running at the end of the test is killed. |
| `tests/commands/` | Integration tests (`//go:build integration`), one file per command, against the real binary, a temp directory and a fake Docker Engine on a unix socket; `report` and `daemon` also get a fake root of the host, with `proc` and `etc/easypanel/projects`, in `TALON_HOST_ROOT`, and `daemon` a fake webhook that tells the test of each request and holds its answer until the test releases it. |
| `.docker/` | The fake VPS: Ubuntu 22.04 with systemd, Docker Engine and Easypanel. The image installs the `.deb` that `make package` builds in its build stage, which copies `Makefile`, `nfpm.yaml`, `version.txt`, `src` and `packaging`: the binary is at `/usr/bin/talon`. `.docker/config`, ignored by git, is mounted at `/etc/talon`. |
| `packaging/` | `talon-upgrade.service`, a oneshot that runs only when `/etc/apt/sources.list.d/talon.list` exists: `apt-get update` of that list alone, then `apt-get install --only-upgrade talon`. `talon-upgrade.timer` starts it every 15 minutes, with a random delay of up to 5 minutes. `talon.service` runs `/usr/bin/talon daemon` as root after `network-online.target` and `docker.service`, with `Restart=on-failure`, `TimeoutStopSec=90s`, longer than the one-minute cap of a cycle, and `ProtectSystem=strict`, since the daemon writes nothing. `postinstall`, `preremove` and `postremove`, the maintainer scripts of the `.deb`, follow what debhelper generates for a timer and a service, with `deb-systemd-helper` and `deb-systemd-invoke`: install enables and starts the timer unless the admin disabled it; with `TALON_NO_UPDATES` set, it disables and stops it, and later upgrades keep it disabled. Install enables and starts `talon.service` unless the admin disabled it, and every upgrade restarts it, which is what turns `agent.version` over; `TALON_NO_UPDATES` does not touch it. Remove stops and masks both units, and purge purges and unmasks them. They restart `talon.service` but never `talon-upgrade.service`: the upgrade runs inside it. |
| `nfpm.yaml` | The `.deb`: the Linux binary at `/usr/bin/talon`, the directory `/etc/talon`, the three units of `packaging/` in `/usr/lib/systemd/system` and its three maintainer scripts. `make package` passes `ARCH` and `VERSION`. |
| `.github/workflows/` | `continuous-integration.yml` (pull requests) and `continuous-deployment.yml` (on `main`): the `release` job cuts the release and attaches `talon-linux-amd64` and `talon_<version>_amd64.deb`; the `publish` job runs `heronlabs/action-apt-repository@v1`, which builds and signs the apt repository from the `.deb` of the release and publishes it through `heronlabs/action-web-server`. `publish` runs in the `main` environment, assumes its AWS role through OIDC and reads the variables `APT_BUCKET_NAME`, `APT_AWS_REGION`, `APT_AWS_ROLE_TO_ASSUME` and `APT_DISTRIBUTION_ID` of the `main` environment. The signing key is the SSM parameter `/talon/APT_GPG_PRIVATE_KEY`, an armored private key with no passphrase. |
| `.githooks/pre-commit` | gofmt, build, vet and unit tests when staged changes touch Go files, `go.mod` or `go.sum`. |

Import rules, enforced by `depguard` in `.golangci.yml`: `core` imports nothing from `application`; `core/entity` imports only the standard library, `infrastructure/docker`, `infrastructure/host` and `infrastructure/easypanel`, where its data comes from; `infrastructure` never imports `application`. `core` imports `infrastructure` only for the types of its interfaces: `docker.Snapshot` in `DockerCollector`, `host.Snapshot` in `HostCollector`, `easypanel.Snapshot` in `EasypanelCollector` and `webhook.ReportResponse` in `ReportSender`. Each interface is declared by the package that consumes it, in the file of its consumer, with the smallest method set that consumer needs; the implementing packages export only their implementations. `application` declares `Doctor` for `DoctorCommand`, `Setup` for `SetupCommand`, `Report` for `ReportCommand`, and `Schedule` and `Cycle` for `DaemonCommand`. `core` declares `HealthCheck` for `DoctorService`, `ConfigReader` and `ConfigWriter` for `SetupService`, and `ConfigGetter`, `DockerCollector`, `HostCollector`, `EasypanelCollector` and `ReportSender` for `ReportService`; `ScheduleService` consumes the same `ConfigGetter`. `environment` declares `Prompt` for `ConfigReaderService`, and `terminal` declares `Echo` for `PromptService`. So `application` imports only `core/entity`, for the report that `Report` returns, and `environment`, `host` and `easypanel` import nothing from talon.

## Commands

| Command | Does |
|---|---|
| `make build` | Static binary in `bin/talon` (`GOOS`, `GOARCH`, `VERSION`, `BIN` overridable) |
| `make package` | Linux binary and its `.deb` in `dist/`, through nfpm (`GOARCH` and `VERSION` overridable) |
| `make lint` | golangci-lint (with gofmt and goimports), actionlint, shellcheck (also on the maintainer scripts in `packaging/`), `go mod tidy -diff` |
| `make lint:fix` | golangci-lint with `--fix` |
| `make test` | Unit tests with the race detector; coverage in `.coverage/unit/` |
| `make test:integration` | Builds an instrumented binary with version `1.2.3` and runs `tests/`; coverage in `.coverage/integration/` |
| `make test:mutation` | gremlins over `src/`, `main.go` excluded, with a timeout coefficient of 20 so a warm test cache does not time mutants out; report in `.coverage/mutation/mutation.json` |
| `make audit` | govulncheck |
| `make up` / `make down` | Start and stop the fake VPS |
| `make watch` | Rebuild the Linux binary into `bin/linux` on every `.go` change; the fake VPS mounts it at `/usr/local/bin`, ahead of the packaged binary on its `PATH` |

`golangci-lint` and `shellcheck` come from brew locally. `actionlint`, `govulncheck`, `gremlins`, `air` and `nfpm` are `go tool`s pinned in `go.mod`. The target names use a colon (`test:integration`), not a dash.

## Conventions

- **Tests:** one `Test<Type>` per source file, in the same package (`command_version.go` and `TestVersionCommand` in `command_version_test.go`), and one `t.Run("Should ...")` per scenario. No table tests, no `for`/`range`. Arrange, act and assert are separated by blank lines, and the single assertion is the last statement: one `if` with one `t.Errorf`. Setup failures use `t.Fatal` inside helpers marked `t.Helper()`. The entities with logic have tests, built from `docker` values decoded from JSON and `host` and `easypanel` values written as literals; the data-only entities (`LastReconcile`, `Reconcile`), `response_*.go` and `client_*.go` have none: the entities and services that use them cover them.
- **Fakes** are written by hand in the test file that uses them (`fakeHealthCheck`), and implement the interfaces of the consumer, declared in the package under test. The filesystem enters as `fs.FS` for reads, and tests pass `fstest.MapFS`, or `os.DirFS` of a `t.TempDir()` whose permissions they change when they need a read to fail; writes go through an `*os.Root` the writer opens on its directory, and tests pass `t.TempDir()`.
- **Integration tests** assert the exit code and the output of the real binary in one condition.
- **Docs:** every declaration, exported or not, has a doc comment that starts with its name and says what it does or holds; a `const` block has one comment for the block. No comment goes inside a function body: a body that does more than one step calls documented, declarative functions, so it reads as a sequence of steps. Each package has its package comment in a `doc.go`. revive checks the exported identifiers and the package comments.
- **Mutants:** a surviving equivalent mutant is fixed by refactoring the code, not by excluding it.
- **Dependencies** enter through constructors (`New<Type>`). Only `main.go` wires.
- **The runtime uses only the standard library.** Every module in `go.mod` is there for a development tool.
- **Errors** wrap with `%w` and a short context prefix (`config:`, `docker:`). `ErrUnexpectedStatus` and `ErrNotFound` are sentinels that tests match with `errors.Is`.
- **Logs** go through `log/slog`: commands log through the injected `*slog.Logger`, one line per result.
- **File names:** the kind comes first, so the explorer groups files by kind: `command_<name>.go` in `application`, `entity_<name>.go` in `core/entity`, `service_<name>.go` in `core` and `infrastructure`, and `response_<name>.go` (an answer of an external API) and `client_<name>.go` in `infrastructure`. A test keeps the name of its file plus `_test.go` (`command_setup_test.go`).
- **Responses and entities:** `response_<name>.go` holds only the struct of an API answer, with no method, function or const; the logic that reads it lives in the entity it fills. Each entity struct has its own `entity_<name>.go`, with the constructor and methods that fill it from the types it reads.
- **Never edit `version.txt` or `CHANGELOG.md`:** the release action owns them.
- **Every change goes through `/supera:ship`:** worktree, pull request, CI green. Nothing is committed to `main` directly and merging is a human action.
